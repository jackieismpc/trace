# 局限性与改进方向

当前范围内的已知局限，写清楚比藏着好。

## 1. expand 依赖原始文件在场且未被修改

索引存的是 `span_id → (offset, len)`，取回靠对原文件做字节切片。文件被修改、
截断或轮转后，这些偏移全部失效。

**处理方式**：索引头部存 `blake2b-256(原文件)` 摘要，`expand` 前重新校验，
不匹配立即以退出码 3 报错。宁可明确失败，绝不静默返回错位数据——下游读者是
Agent，喂给它一段「看起来是合法 JSON、实际是错位切片」的数据，它会一本正经地
推理出错误结论，而且毫无征兆。

**规避方式**：可预见文件会被轮转时，生成骨架时加 `--detach <目录>`，把每个 span
的原文单独物化一份，用空间换可用性（代价是空间接近翻倍）。

## 2. 性能上界低于同架构的 Rust 实现

实测数据见[验证报告](验证报告.md)第五节，三条验收线全部达标，但绝对值低于
Rust 实现能达到的水平。

若未来出现「单机批量处理数百 GB Trace」这类需求，热点扫描器可单点替换为 Rust
扩展（maturin 构建，接口不变），其余 Python 代码零改动——分层设计为这条路留了口。
索引文件是语言中立的 struct 布局，Rust 版与 Python 版理论上可以互读同一份 `.idx`。

## 3. token 计数默认是估算值

默认按 `chars / chars_per_token` 估算（拉丁 4.0、CJK 1.5），零依赖且确定性。
装了 `[tokens]` extra 才用 tiktoken 精确计算。

骨架末尾**始终标注用的是哪种方法**——估算值和精确值可能差出 30%，而下游可能拿
这个数字做「装不装得下」的决策，不标注就是在制造隐性风险。请求精确计数但未安装
extra 时会自动回退到估算，并在方法说明里写明「已回退」，不会让人误以为拿到的是
精确值。

## 4. SpanKind 的启发式推断可能出错

类型推断的优先级是：`mlflow.spanType`（Explicit）> OTel GenAI 语义约定
（Convention）> span name 正则（Heuristic）> Unknown。最后两档都可能猜错。

**兜底不是「追求推断零错误」，而是 `KindSource` 可信度标记**：骨架对启发式结果
打 `⚠`。一个叫 `search_tool` 的 span 被猜成 TOOL 多半是对的，但如果它实际是个
子 Agent，读者会用「工具出错」的思路排查「模型出错」的问题。标了 Heuristic，
Agent 至少知道这条推理链的地基是软的，必要时可以先 expand 验证类型。

## 5. grapheme cluster 默认不处理

截断默认按 Unicode 码点计数与切分：不会劈开多字节字符（这是在 str 层操作的天然
好处），但 `👨‍👩‍👧` 这类 ZWJ 序列由多个码点拼成，按码点截可能把家庭切散；
组合字符（`é` = `e` + U+0301）同理。

`--strict-grapheme` 会引入 `regex` 包用 `\X` 按 grapheme cluster 截断。默认不启用
是为了零依赖，且这个差异只影响截断预览的**显示**，不影响可取回性——完整内容永远
能凭 `span_id` + 字段路径原样取回。

## 6. 定位为单机离线工具

不做流式摄入、在线服务和多 Trace 聚合分析。输入是已落盘的 Trace 文件，输出是
骨架与索引，进程无状态。埋点采集交给 MLflow / OTel SDK，可视化 UI 与存储后端
都不在范围内。

## 7. OTLP 格式的多层数组导航需要一次额外的结构扫描

MLflow 的 spans 数组路径固定（`data.spans`），一次定位即可。OTLP 是
`resourceSpans[] → scopeSpans[] → spans[]` 三层嵌套，跳到下一个元素需要跳过当前
元素，相当于对文件多做一遍结构扫描（纯 C 级正则前进，不解析值）。常见的
「单 resourceSpans × 单 scopeSpans」情形下这部分开销可忽略。

## 8. 守恒律的表述相对方案原文做了收紧

方案原文的不变量⑤写的是「`elided_depth` 之和加存活节点数等于原节点数」。当一个
被删节点有多条存活分支时，它会被多个子节点的 `elided_depth` 各计一次，那条等式
并不成立。

实现里把守恒律改成严格形式：**每个被删节点恰好归属于一个占位节点**（它的最近存活
祖先下、按类型分组的那个），于是

    存活节点数 + Σ 占位节点汇总数 = 原节点数

恒成立，并由 hypothesis 在随机森林 × 随机规则集上钉死。`elided_depth` 退回其本义
——「这条边上折叠了几层」，只用于展示。

## 改进方向

按优先级：

1. **MCP Server**（`mcp_server.py`）——把 `get_skeleton` / `expand_span` 暴露成两个
   MCP tool。工具的目标用户本来就是 Agent，MCP 让它用原生工具调用消费，比经由
   shell 转一手更直接：不用学 CLI 语法、不用解析 stdout 文本、错误也是结构化的。
   架构上只需在 `cli.py` 旁平行加一个模块，核心逻辑零改动。
2. **`tracelens diff traceA traceB`**——「上次好的这次坏了」是最常见的排查入口。
3. **分级骨架 `--detail low|high`**——同一份索引出多档视图。
4. **扫描器下沉为 Rust 扩展**——覆盖极端规模场景，见局限 2。
