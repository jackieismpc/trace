# tracelens 测试总览

本项目的测试分三层，各自回答一个不同的问题：

1. **单元 / 属性 / 快照测试**（`tests/`）——每个模块的行为对不对？
2. **脚本级 demo 与基准**（`scripts/`）——端到端的信息可达性与性能达标吗？
3. **真实 Agent 盲测**（`tests/real_agent_run/` + `scripts/blind_bug_fixture.py`）——
   一个真实 LLM 事先不知道答案时，能不能只凭骨架 + 展开查出根因？

三层合起来覆盖：正确性（第 1 层）、可达性与性能（第 2 层）、以及「可达的证据能否被真实
Agent 用起来」（第 3 层）。下面逐项说明每个测试的作用。

---

## 一、单元 / 属性 / 快照测试（`tests/`，190 项，覆盖率 92%）

用 `uv run pytest` 运行。

| 文件 | 作用 |
| --- | --- |
| `test_scanner.py` | 字节级扫描器的边界用例，并用 **hypothesis** 拿标准 `json` 解析做交叉验证——扫描器识别出的 span 边界必须与真实解析一致。 |
| `test_ingest.py` | ingest 层：格式嗅探（MLflow / OTLP）、双适配器、`SpanKind` 的分级推断（Explicit / Convention / Heuristic / Unknown）。 |
| `test_topology.py` | **五条拓扑不变量**的形式化验证（剪枝正确性的核心）。最关键一条：骨架上读到的祖先关系，在真实执行中一定成立；删节点时子节点重挂最近存活祖先、节点数守恒。由 hypothesis 在随机森林 × 随机规则集上钉死。 |
| `test_truncate.py` | 三种截断策略（head / tail / head_tail）、UTF-8 边界安全、自描述的 `✂` 标记。 |
| `test_rules.py` | 规则匹配与四层配置叠加中的规则部分；对应「规则是数据、可动态调整」的要求；非法规则应显式失败。 |
| `test_config.py` | 四层配置叠加：内置默认 < TOML < 环境变量 `TRACELENS_*` < CLI 参数。 |
| `test_paths.py` | 点路径（`$.attributes[...]`）解析与字节区间定位。 |
| `test_index.py` | 索引与展开——**「字节级一致」承诺的闭环**：`expand` 输出必须等于原文件切片；含摘要校验。 |
| `test_render.py` | 三种渲染（tree / json / md）+ 预算收紧；用 **syrupy 快照**锁定输出形态。 |
| `test_cli.py` | 子命令行为、全链路走查、**退出码语义**（0/1/2/3/4）。上层脚本与 Agent harness 依赖这些码区分「没找到」和「数据坏了」。 |
| `test_demo.py` | 对下面 demo 脚本的集成测试，保证自验流程本身不腐化。 |
| `conftest.py` / `strategies.py` | 公共夹具；hypothesis 的随机 JSON 文档与随机 Trace 策略。 |

## 二、脚本级 demo 与基准（`scripts/`）

| 脚本 | 作用 |
| --- | --- |
| `make_demo_fixture.py` | 确定性生成一份**故意植入 bug** 的 demo Trace（SQL 表名写错、错误被吞）。体积分布刻意贴近真实：每轮携带全量历史、近似平方级膨胀。 |
| `demo_investigate.py` | **自验实验组**：用 tracelens 定位根因的完整闭环。不调 LLM，论证「根因证据落在 Agent 能拿到的那部分数据里」。 |
| `demo_control.py` | **自验对照组**：不用工具，把原始 Trace 前 128K token 直接喂给模型，演示唯一的错误证据根本进不了窗口。 |
| `bench_scanner.py` | 扫描器吞吐微基准（验收线 ≥ 200 MB/s）。 |
| `bench_pipeline.py` | 全流程性能基准 + 堆内存峰值（核心性质：堆占用与「最大单个 span」成正比，而非与文件大小成正比）。 |
| `collect_langgraph_trace.py` | 可选：用真实 LangGraph Agent 采集一份真实 MLflow Trace，替换合成 fixture。 |
| `blind_bug_fixture.py` | **真实 Agent 盲测的 trace 生成器**（见下节）。与 `make_demo_fixture` 的关键区别：根因用运行时随机熵选定并密封，连测试设计者事先都不知道。 |

> 注：`demo_investigate.py` / `demo_control.py` **刻意不调用任何 LLM**——它们验证的是
> 「信息可达性」这个比模型能力更硬的约束。「可达的证据能不能被真实 LLM 用起来」由第三层
> 的真实 Agent 盲测补上。

## 三、真实 Agent 盲测（`tests/real_agent_run/`）

这是把**真实 LLM Agent 放进回路**的一层，补上了前两层刻意不碰的环节。完整方法与评分见
[真实 Agent 测试报告](真实Agent测试报告.md)，归档产物见
[`tests/real_agent_run/`](../tests/real_agent_run/)。

**它验证什么**：一个冷启动、事先不知道 bug 的 Claude Sonnet 子 Agent，只拿到 16 KB 骨架 +
`tracelens expand`，能否在一份 3.8 MB、根因埋在第 300 万字节的 Trace 上精确定位根因；并与
「把原始 JSON 截断进 128K 窗口」的常规做法（对照组，同一模型）对比。

**盲测协议**：根因由 `blind_bug_fixture.py` 用 `os.urandom` 在 4 个原型间随机选定，答案当场
密封，设计者在子 Agent 交卷前不看骨架、不开封。

**结论**：实验组精确命中（数据足迹占全文 1.13%）；对照组因证据落在窗口外而无法定位，并诚实
判定「证据不足」（未幻觉）。

**如何重跑**：见 [`tests/real_agent_run/README.md`](../tests/real_agent_run/README.md)。每次重跑
都会换一个新的、你我都不知道的 bug。

## 快速命令

```bash
uv run pytest                                   # 第一层：190 项
uv run pytest --cov --cov-report=term-missing   # 覆盖率（当前 92%）
uv run python scripts/demo_investigate.py       # 第二层：实验组
uv run python scripts/demo_control.py           # 第二层：对照组
uv run python scripts/bench_pipeline.py 200     # 第二层：性能
uv run python scripts/blind_bug_fixture.py out/blind_trace.json out/blind_answer_key.SEALED.json  # 第三层：新盲测
```
