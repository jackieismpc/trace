# tracelens 测试方案

> 本文说明「为什么测 / 怎么测 / 测出什么」。测试分三类数据源，覆盖三条独立证据线；
> 实测数字见[验证报告](验证报告.md)。仓库内所有数字都可原地复现（见文末「运行全部测试」）。

## 0. 测试架构：三类数据源 → 三条证据线

采集从哪来（数据源），决定了测的是「格式对不对」还是「能不能查到根因」：

| 数据源 | 生产方 | 性质 | 证据线 |
| --- | --- | --- | --- |
| **opencode 插件**（`opencode-plugin/`） | 真实 opencode 会话，`session.idle` 时由插件导出标准 MLflow `trace.json` | **真实采集**、确定性弱（模型行为不定） | ① 采集闭环：插件产出格式可被 tracelens 全流程处理 |
| **demo fixture**（`scripts/make_demo_fixture.py`） | 脚本生成，植入 SQL 表名错误、错误被吞的 bug | 合成但**确定性、可复现** | ② 信息可达性自验（不调 LLM） |
| **blind fixture**（`scripts/blind_bug_fixture.py`） | `os.urandom` 随机选根因，答案当场密封（SEALED） | 合成、随机、**设计者不知答案** | ③ 真实 Agent 盲测（LLM 进回路） |

工具正确性/边界、性能、单测质量是横切在三条证据线之上的通用校验。

```
                     ┌─ ① 真实采集：opencode 插件 → trace.json → inspect/skeleton/expand
真实/合成 trace.json ─┼─ ② 可达性：demo_investigate（实验组） vs demo_control（对照组）
  （标准 MLflow 形态） └─ ③ 盲测：blind_bug_fixture（SEALED 答案）→ 不知情 LLM 查根因 → 开封对分
```

---

## 1. 证据线 ①：真实采集闭环（opencode 插件）

**作用**：验证主链路「opencode 会话 → 插件自动导出标准 MLflow trace.json → tracelens
inspect/skeleton/expand」真实可用。这是本项目采集层（方案 A）的验收。

**使用方法**：

```bash
# 一次跑通整条链路（需要本机可用模型，如 mydeepseek）
bash scripts/opencode_collect_demo.sh
# 产物：out/opencode_demo.trace.json + out/opencode_demo.skeleton.txt + 字节级校验结论

# 手动等价步骤
cd opencode-plugin && npm ci && npm run build          # 产出单文件 dist/plugin.js
mkdir -p .opencode/plugins && cp dist/plugin.js .opencode/plugins/tracelens.js
opencode run "运行 pwd 命令查看当前目录，然后简单回答确认"   # 跑任意会话
tracelens inspect --input .tracelens/traces/<会话>.trace.json
```

**测试结果**（2026-08-05 实测，opencode 1.18.13 / mydeepseek）：

| 项 | 结果 |
| --- | --- |
| 插件产出 | 真实会话自动生成 `.tracelens/traces/*.trace.json`（标准 MLflow 形态） |
| span 结构 | 1 根 `AGENT` + 2 轮 `LLM` + 1 `TOOL`（`bash: pwd`），父子关系正确 |
| inspect | `格式: mlflow`、span 总数/根节点正确 |
| skeleton | 4 span 全部保留，token 预算内渲染 |
| expand 字节级 | 4/4 span 取回字节均与原文逐字节一致 |

**不进 CI 的原因**：真实采集需要模型与网络，属「真实证据」，在 CI 中由
`tests/fixtures/opencode_sample.trace.json`（插件确定性产出的固定样本）做离线闭环替代
（见 `tests/test_opencode_plugin_trace.py`）。

## 2. 证据线 ②：信息可达性自验（不调 LLM）

**作用**：在数据层面论证「根因证据是否落在 Agent 能拿到的那部分数据里」，不依赖任何模型发挥。
命题是：128K 窗口下原始 Trace 只能塞进约 14%，且 Agent **无法选择**塞哪部分；
用 tracelens 后 Agent 拿到 100% 拓扑 + 自选关键细节，只占窗口约 3%。

**使用方法**：

```bash
uv run python scripts/make_demo_fixture.py out/demo_trace.json   # 确定性植入 bug 的 fixture
uv run python scripts/demo_investigate.py                        # 实验组：定位根因
uv run python scripts/demo_control.py                            # 对照组：证据进不了窗口
```

**测试结果**：demo fixture 411 span / 3.8 MB，骨架 16 KB（原文 0.41%）；实验组约 3,963 token
（窗口 3.1%）命中根因；对照组 128K 只装下全文 13.9%，唯一 ERROR 落在窗口外。

---

## 3. 证据线 ③：真实 Agent 盲测（LLM 进回路）

**作用**：补上「证据可达之后，一个真实、事先不知答案的 LLM 能否只凭骨架 + expand 查出根因」。
根因由 `blind_bug_fixture.py` 用 `os.urandom` 在 4 个「静默失败」原型间随机选定，答案当场密封；
测试设计者在被测 Agent 交卷前不看骨架、不开封。

**使用方法**：

```bash
uv run python scripts/blind_bug_fixture.py out/blind_trace.json out/blind_answer_key.SEALED.json
# 把骨架交给不知情 Agent → 只用 expand 查根因 → 完成后开封 SEALED 对分
```

**测试结果**：抽中 `missing_config_key` 原型；411 span / 3.97 MB / 1,154,189 token，根因在
128K 窗口外。实验组（16KB 骨架 + expand）**精确命中** span_id + 错误原文 + 传播链，数据足迹
13,078 token；对照组填满窗口仍**无法定位**，并诚实判定「证据不足」（未幻觉）。
> 诚实标注：单实例单次；成功率需多种子多原型统计（生成器已支持自动换种子）。

## 4. 工具正确性与边界（横切校验）

**作用**：逐条验证四条设计承诺与退出码语义，防止「看起来合法、实际错位」的静默失败。

| 承诺 | 测试 |
| --- | --- |
| ① 字节级一致（构造性） | expand 即 `buf[off:off+len]`，独立复跑根因 span 的 blake2b 与原文切片一致 |
| ② 宁可失败不喂错 | 篡改原文件 1 字节 → expand 退出码 3，而非返回错位切片 |
| ③「没找到」与「数据坏了」可区分 | 不存在/歧义 span_id → 退出码 2 |
| ④ 硬保护 | 激进折叠下根 + ERROR 路径仍全部保留在骨架中 |

**测试结果**：全部通过（见验证报告 §三）。

## 5. 性能（横切校验）

**作用**：验证 mmap 只读 + 逐 span 解析的堆占用与「最大单个 span」成正比，而非文件大小。

**使用方法**：`uv run python scripts/bench_pipeline.py 200`（200 MB / 25,878 span）。

**测试结果**：扫描 833 MB/s（验收线 200）、全流程 3.20 s、堆峰值 83.7 MB（200 MB 文件）。

## 6. 质量数据（单测 / 静态检查）

**作用**：行为级回归 + 类型级约束，确保每次提交不破坏任何一条证据线。

## 7. 运行全部测试

```bash
# Python 核心 + 覆盖率（含插件闭环样本）
uv sync --dev
uv run ruff check . && uv run ruff format --check .
uv run mypy
uv run pytest --cov --cov-report=term-missing --cov-fail-under=85

# opencode 插件（Node/TS）
cd opencode-plugin
npm ci
npm run typecheck && npm run build
npm test

# 证据线脚本（可复现）
uv run python scripts/make_demo_fixture.py out/demo_trace.json
uv run python scripts/demo_investigate.py
uv run python scripts/demo_control.py
uv run python scripts/blind_bug_fixture.py out/blind_trace.json out/blind_answer_key.SEALED.json
uv run python scripts/bench_pipeline.py 200

# 真实采集（需模型与网络）
bash scripts/opencode_collect_demo.sh
```
